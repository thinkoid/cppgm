cppgm is an ultra-fast C++ compiler

- **Try it.** [incpption.com](https://incpption.com) runs the compiler in a
  browser. There, cppgm compiles itself on your device.
- **Read about it.**
  [How I Built a Compiler That Is Faster Than GCC and Clang](https://medium.com/@vishvananda/how-i-built-a-compiler-that-is-faster-than-gcc-and-clang-4c8c1d4818fa)
  explains how the reference compiler was built. The origins of the proect can
  be found in the blog series that begins with
  [I Spent 2 Billion Tokens Writing a C++ Compiler So You Don't Have To](https://medium.com/@vishvananda/i-spent-2-billion-tokens-writing-a-c-compiler-so-you-dont-have-to-d3e4eec4781e).
- **Take the course.** This repository also includes instructions and tests
  that can be used as a scaffold for an agent to build its own C++ compiler with
  maximum efficiency. To try it, point your agent at
  [cppgm-assignments](https://github.com/vishvananda/cppgm-assignments). This
  export has the scaffolds, the handouts, the tests and the reference tools.
  Its references are generated by this compiler.

## Performance

**O3 speedups. Higher is better.** Each cell shows three hosts, from top to bottom: **EPYC**, **CI Intel** and **Intel**. EPYC and CI Intel are GitHub-hosted runners. Intel is a dedicated machine. The colors go from green through yellow and orange to red; red is 0.50× or less. `n/m` means not measured. `n/a` means that the comparison does not apply. `*` marks a result from a commit that is 10 or more commits behind `main`, or that is not on `main`. A result from a commit that is 100 or more commits behind `main` is not shown; its place is empty. [Measurement age](https://github.com/vishvananda/cppgm/blob/benchmark-badges/freshness.md) lists every measured commit. Click a badge to see its details.

What the rows measure:

- Compilation and runtime are CPU time. The index-cpp runtime is elapsed time.
- Godot: a full build, with SCons and linking.
- Boost: the C++ tests are compiled with assertions enabled and run natively. The GDB test is checked for correctness only.
- Internal C++ subset: a fixed set of course sources is compiled.
- Wasm: the runtime calls warmed exports in one pinned engine.
- cppgm: the self-built compiler is compared with the compilers that GCC and Clang built.
- cppgm · WASI: compilation is cppgm or Clang building cppgm for WASI. Runtime is those two WASI compilers rebuilding cppgm in one pinned engine.

Methods: [public programs](benchmarks/public/README.md) ([O0 and per-host results](https://github.com/vishvananda/cppgm/blob/benchmark-badges/public-hosts.md)), [index-cpp](benchmarks/index_cpp/README.md), [simdjson](benchmarks/simdjson/README.md), [internal C++](benchmarks/internal/README.md), [Boost](benchmarks/boost/README.md), [Godot](benchmarks/godot/README.md), [Wasm](pa37/benchmarks/README.md), [cppgm](benchmarks/self_compile/README.md), [cppgm · WASI](scripts/experimental/README.md#full-compiler-benchmark). See also [how to refresh the dedicated Intel measurements](docs/performance/intel-benchmarks.md).

## Caveats

- The [required C++11/14/17 profile](LANGUAGE_PROFILE.md) covers selected features. It is not full conformance to each edition.
- C++20 and C have partial support. The profile lists the selected C++20 features. The optional [PA38](pa38/README.md) compiles C sources in the `c17` and `gnu17` modes.
- The targets are Linux x86-64, Intel macOS and wasm32 (`wasm32-unknown-unknown` and `wasm32-wasip1`, [PA37](pa37/README.md)).
- [Integrated assembly](pa29/README.md) is complete for its documented x86-64 profile. It is not a general assembler.
- The compiler has no C++ standard library of its own. Use the library that is installed on the host.
- The compiler can contain bugs.
- The generated code can be slow for program shapes that the benchmarks do not cover.

## Build and validate

The main target is Linux x86-64. Install a C++11 host compiler, GNU make,
Bash, Perl and Python 3. Later checks also use binutils and a debugger.

```sh
make CXX=g++ CPPGM_HOST_CXX=g++
make test-report
make inception
```

To get only the compiler, check out `dev/` without the course data and build
`cppgm`:

```sh
git clone --depth 1 --filter=blob:none --sparse https://github.com/vishvananda/cppgm.git
git -C cppgm sparse-checkout set dev
make -C cppgm/dev cppgm CXX=g++ CPPGM_HOST_CXX=g++
```

To build with Clang, pass `CXX=clang++ CPPGM_HOST_CXX=clang++`. `CC` does not
select the C++ host compiler. Use one host toolchain for a whole build.

Each [release](https://github.com/vishvananda/cppgm/releases) has packages of
the tools and the LowIR library for Linux x86-64 and Intel macOS, the tools as
WASI modules, and a source archive. See
[reference and version exports](TESTING_AND_REFERENCES.md#reference-and-version-exports).

[The macOS guide](docs/intel-macos.md) describes Intel macOS support and its
optional checks.
