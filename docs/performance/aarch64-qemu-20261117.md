# Arm code generation under QEMU, 2026-11-17

Self-built cppgm took **2.25× as long** as Clang-built cppgm to rebuild the compiler,
or **0.44× its throughput**. With 24 jobs the paired means were **129.3 s**
for Clang-built cppgm and **290.8 s** for self-built cppgm. Aggregate CPU time
gave a **2.27×** time ratio. Each of the twelve builds produced the same 492
objects and the same executable, which also matched the self-built compiler input.

## Full PA35 compiler rebuild

A was a static Linux AArch64 cppgm built by Clang 22.1.2 at `-O3`. B was the
same compiler built by cppgm at `-O3`. Both ran under QEMU user mode 10.2.1,
`-cpu cortex-a53`, on a shared x86-64 Intel Xeon E5-2696 v4. Each invocation
started with an empty object directory and rebuilt the same sources and target
headers. Both used `--target=aarch64-linux-gnu -fno-strict-aliasing` and the
same x86-hosted GCC 14.3 cross driver and LLD 22.1.2 for the final static link.
The four calibration invocations also warmed the host filesystem cache.

Each case used a fixed host CPU affinity. The public programs used three
paired blocks and two calibration blocks. The three short scalar kernels used
four paired blocks, three calibration blocks and eight executions per block
position. The NEON row uses a five-block repeat with three calibration blocks
and three executions per position. An earlier three-block run returned
1.06× with a paired range of 0.90–1.31×.
The spreads matter when interpreting results close to parity. Native Arm
hardware is needed for cycle counts and for hardware speed comparisons.

All four kernels run through the same Clang-built caller. In the NEON workload,
both compilers emit vector arithmetic for `mix` and `scale`. The generated
functions each take six instructions with cppgm and three with Clang. The
difference is three register copies per function. The caller performs the
iteration, input generation and checksum in both runs.

## Where the extra instructions execute

| Compiler input | Clang-built instructions (billions) | Self-built instructions (billions) | Self/Clang-built |
| --- | ---: | ---: | ---: |
| `aarch64/vector.cpp` | 0.567 | 2.465 | 4.35× |
| `opt/loop_vectorizer.cpp` | 2.598 | 12.690 | 4.88× |
| `driver/host_environment.cpp` | 0.984 | 4.528 | 4.60× |

These are individual PA35 compile commands replayed from the full rebuild.
The paired compilers produced byte-identical objects in all three cases.

- **Compiler optimizer.** While compiling `loop_vectorizer.cpp`, both
  compilers entered the inner loop of `map_instruction_blocks` 1,919,004
  times. The hot translated block contained 41 Arm instructions in the
  self-built compiler and seven in the Clang-built compiler. The former
  emitted 20 register-to-register moves, two multiplies for powers of two
  and a materialized Boolean before the branch. Clang used scaled addressing
  and branched directly on flags. This is a small self-build workload for
  testing operand selection and compare/branch folding.
  [Compiler source](../../dev/src/opt/function_ir.cpp)
- **Bubblesort.** The adjacent-element compare ran 12,475,000 times on both
  sides. cppgm used a 24-instruction block with stack traffic and integer
  extensions. Clang kept the preceding element in a register and emitted
  `ldr w16, [x13]`, `cmp w14, w16`, `b.gt`. The complete programs executed
  643.4 million and 88.6 million guest instructions respectively.
- **Puzzle.** A frequently taken block in `Trial(int)` executed 53,889,000
  times in each program. cppgm loaded its index from the stack, recomputed
  the address, loaded the element and tested it in nine instructions.
  Clang used a post-indexed load followed by `cbz`.

## Reproduction

Use the same frozen Linux ELF files for a native Arm follow-up. For the
self-build, the compiler images embed the target header search paths. Recreate
those paths on the Arm machine or bootstrap both compilers against its native
Arm toolchain. Compare them on the same source tree, headers and job count
with a common linker. The local runner retains
every timing observation, output hash and translation-unit build command.
